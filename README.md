# 校园网自动登录守护脚本


>
> 一个常驻 Windows 后台、断网即自动重连校园网的小工具——开机联网后**全程无感**，不用再手动打开网页输账号密码。

## 一、它解决什么问题

使用笔记本远程控制主机的时候可能会遇见网络连接中断；或者在宿舍连上校园网后，每次都要打开浏览器、被重定向到认证页、手动输入账号密码
这个脚本只做一件事-- 确保校园网保持畅通，主要实现过程如下

```
检测是否真正联网  →  被认证网关挡住？  →  自动调用认证接口登录  →  复核是否恢复上网
        ↑                                                                    │
        └────────────────────────  循环守护（默认每 30 秒）──────────────────────┘
```



## 二、主要功能

- **断网自动登录**：周期性检测联网状态，发现掉线立即自动认证，无需人工干预。
- **登录后联网复核**：不只看网关返回，再实际探测一次是否真的能上网，避免“假成功”。
- **健壮的联网探测**：以 `generate_204` 认证探测端点为主、HTTPS 站点兜底，能正确识别“连上了 WiFi 但未认证”的假联网状态。
- **失败自动重试**：指数退避（5s → 10s → 20s），针对“IP 会话不存在”这类会话尚未建立的瞬时错误尤其有效。
- **设备信息自动获取**：内网出口 IP、主机名、MAC 自动探测，换设备 / 换网络也能跑；也支持在配置里固定。
- **开机自启**：一条命令注册 Windows 计划任务，登录系统后以无控制台窗口方式后台运行。
- **单实例守护**：避免重复启动、重复登录。
- **日志轮转**：日志自动按大小切分，只保留最近若干份，不会无限膨胀。
- **安全设计**：账号密码只放在本地不入库的配置文件里；日志只记录中文结果，**绝不记录含账号密码的请求地址**。
- **诊断命令**：`--diag` 一键查看环境、配置、本机 IP/MAC 与联网状态，方便排查。

## 四、本地运行步骤

### 1. 环境要求

- Windows 10 / 11，Python 3.8 及以上（开发环境为 Python 3.10）。
- 仅依赖 `requests`。

### 2. 安装依赖

```bash
win+R 输入cmd 输入以下命令
pip install -r requirements.txt
```

### 3. 创建配置文件


 在cmd里面输入下面命（把模板复制一份并改名 ）

```bash
copy campus_login.ini.example campus_login.ini
```

用记事本打开 `campus_login.ini`，在 `[account]` 段填入你的校园网账号密码：

```ini
[account]
user_id = 你的学号
password = 你的密码
```

> 网关参数和运行参数一般不用动：`wlanuserip / mac / hostname` 留空会自动获取。

### 4. 先跑一次诊断（推荐）

```bash
python campus_login.py --diag
```

会打印本机出口 IP、主机名、MAC、配置是否齐全、自启状态以及当前是否在线，便于确认环境。

### 5. 单次测试

```bash
python campus_login.py --once
```

立刻检测一次：在线则不重复登录，离线则尝试登录，日志会同时打印到控制台，方便确认效果。

### 6. 常驻守护（手动运行）

```bash
python campus_login.py
```

进入后台循环，每 30 秒检测一次。想让它同时在屏幕上打印日志，加 `--verbose`。按 `Ctrl + C` 可停止。

### 7. 设置开机自启（实现“全程无感”）

```bash
python campus_login.py --install
```

注册名为 `CampusAutoLogin` 的 Windows 计划任务，以后每次登录系统都会自动在后台运行（无黑窗口）。取消自启：

```bash
python campus_login.py --uninstall
```

> 若注册失败，请用“管理员身份”打开命令行再执行。

## 五、它是怎么判断“能不能上网”的

刚连上需要认证的校园网时，系统会显示“已连接”，但其实**所有 HTTP 访问都会被劫持到认证页面**。脚本用两层判断：

1. **`generate_204` 端点为主**：真正联网时服务器返回 `204 No Content`；被网关拦截时会被重定向成 `200/302` 的认证页。状态码严格区分，能识别“假联网”。
2. **HTTPS 站点兜底**：认证网关无法对 HTTPS 静默劫持（会因证书不匹配直接连接失败），所以能正常完成 HTTPS 请求，就说明确实联网了。

多个国内可达的探测端点，任一确认在线即视为在线，避免单点误判。

## 六、配置项说明

| 配置项 | 位置 | 说明 |
|---|---|---|
| `user_id` / `password` | `[account]` | 校园网账号密码，必填，仅保存在本地不入库的 ini 中 |
| `base_url` | `[gateway]` | 认证网关地址，默认内置，已适配当前校园网 |
| `wlanuserip` / `mac` / `hostname` | `[gateway]` | 留空自动探测；自动探测不对时可抓包后手动固定 |
| 其余网关参数 | `[gateway]` | 学校认证接口的固定参数，内置默认已可用，一般不用改 |
| `check_interval` | `[settings]` | 联网检测间隔（秒），默认 30 |
| `login_timeout` / `check_timeout` | `[settings]` | 登录 / 探测超时（秒） |
| `max_retry` / `retry_backoff` | `[settings]` | 一轮登录最大次数与退避基数 |
| `log_level` | `[settings]` | 日志级别，默认 INFO |

## 七、合成数据与隐私安全说明

- 本项目是网络自动化工具，**不涉及任何业务用户数据**，也不采集同学的姓名、手机号、学号、成绩等信息。
- 配置模板 `campus_login.ini.example` 中账号位均为 `你的账号 / 你的密码` 占位符；真实的 `campus_login.ini` 已在 `.gitignore` 中，**不会进入仓库**。
- 日志只记录网关返回的中文结果（如“认证成功 / 认证失败，原因…”）和异常类型名；`requests` 抛出的异常文本会带完整请求地址（含账号密码），代码对此专门做了处理，**只记异常类型、不记地址**。
- 认证采用 GET 方式是校园网网关的既有协议要求，账号密码仅在本机与校园网认证网关之间传输，不经过任何第三方。

## 八、已知问题与限制

- 网关地址、`wlanacname` 等参数是按当前学校网络抓包内置的，**换学校 / 换校区网络时需要在 `[gateway]` 中改为对应参数**。
- 极少数网络环境下，自动探测到的 MAC 与认证接口要求的不一致可能导致登录失败，此时可从浏览器认证地址里复制 `mac` 参数填到 ini 固定（见 `--diag` 与故障排查）。
- 只做了 Windows 开机自启（计划任务）；macOS / Linux 需自行用 launchd / systemd 配置。
- 没有调用大模型，核心逻辑是网络检测 + 认证接口调用 + 状态复核，符合“跑通真实闭环”的目标。

## 九、常见故障排查

- **提示“未找到配置文件”**：还没复制 `campus_login.ini`，按第四步操作。
- **一直“IP 会话不存在”后又成功**：这是正常现象。刚连上 WiFi 时认证服务器还没为该 IP 建立会话，脚本会自动退避重试。
- **提示“账号已经在线，不允许更多登陆”**：说明账号在别处 / 上一会话还挂着，脚本会复核是否其实已经联网，若已联网即视为成功。
- **`No module named requests`**：当前 Python 没装依赖，执行 `pip install -r requirements.txt`，或换用已装 requests 的解释器。
- **登录一直失败**：先 `--diag` 对比“本机出口 IP / MAC”与浏览器认证地址中的参数是否一致，不一致就在 ini 里固定。
- **想确认自启是否生效**：`--diag` 会显示“开机自启：已注册/未注册”。
- **日志中文乱码**：日志是 UTF-8 编码，Windows PowerShell 默认按 GBK 读取会花屏。查看时务必加 `-Encoding UTF8`：
  ```powershell
  Get-Content campus_login.log -Tail 20 -Encoding UTF8        # 最近 20 行
  Get-Content campus_login.log -Tail 20 -Wait -Encoding UTF8   # 实时跟踪（Ctrl+C 退出）
  ```

## 十、协同复盘（AI 协作过程）

这个项目最早是我为了少输几次校园网密码手写的小脚本，后来在 AI 辅助下逐步补齐了工程化部分。我先用浏览器抓包确认了认证网关的真实请求参数，把“断网→登录”这一最小闭环跑通，再让 AI 协助我做重试、日志和配置拆分。过程中我坚持自己把关关键判断：联网状态不能只看网关返回，必须实际探测复核，所以加了 `generate_204` 与 HTTPS 双层检测；账号密码绝不能进代码和日志，于是把凭据移到被忽略的 ini、并让日志只记异常类型。我踩过最深刻的坑是：一次网关不可达时 `requests` 的异常信息里**带出了含明文密码的完整 URL**，据此我专门改成只记录异常类型，并清理了历史日志。我也修正了成功码可能是数字或字符串、设备 IP 会变化等问题，每次改完都用 `--diag`、`--once` 和故意断网来验证。取舍上，我只做断网重连这一条闭环，没有追求图形界面或多平台部署，优先保证稳定、可复验、可解释。
